# G4 implementation evidence

## S1.1: Fixed request inputs and cancellation

- Each open/updateData/render captures cloned schema and data before awaiting. Uses the existing supported `deepClone` implementation (Date, undefined, bigint retained); no structuredClone or JSON copy.
- Request identity, document generation, captured target and abort signal revoke older publication rights. Supersession/document change/destroy return a discriminated cancellation result without waiting for external promises. A failed newer request cannot restore an older request.
- Renderer failure bookkeeping is local to each request. Loader code remains owned by the material Host; request cancellation prevents its result from entering request state.
- Request-local FontManager generations prevent cancelled font loads from injecting styles after cancellation. Actual font readiness/budgets remain S3 work.
- Render status is independent of completed output. open clears previous pages and metrics before validating the new document.
- Validation: `pnpm exec vitest run --dom packages/viewer/src/render-session.test.ts packages/viewer/src/host-lifecycle.test.ts packages/viewer/src/text-image-materials.test.ts`: 3 files, 13 tests pass (2026-10-12).

## S1.2: Candidate output and owned cleanup

- Capture target document/mount and zoom at request start. Build DOM in a detached candidate; publish pages, metrics, input snapshot and diagnostics after Host/document/request checks. Same-document failure preserves the last complete output; explicit open clears it.
- render/getRenderSize acquire per-output-item signal/onDispose contexts. Local render failure skips getRenderSize; either failure disposes that item's resources and uses declared/laid-out geometry for its placeholder. Candidate cancellation, preview replacement and destroy release only their owned resources.
- Completed computation does not abort its displayed output signal. Output cleanup runs in reverse registration order, continues after errors, and aggregates into destroy. The destroy Promise is published before abort listeners can reenter, and waits for already acquired async cleanup. Late errors remain separately inspectable.
- Diagnostic callback exceptions cannot undo a committed version; late hook failure delivery checks the originating request rather than the latest callback.
- Architecture chapters 06/24 describe the implemented request/commit boundary and explicitly identify remaining Gate work.
- Validation before repository rerun: request/lifecycle tests 2 files, 15 tests pass; request/audit/print fixture regression 3 files, 33 tests pass. R4's prior two failures were obsolete fault injection/cleanup-phase expectations; the corresponding behavior checks remain covered.
- Final checks (2026-10-12): R1 `pnpm build`, R2 `pnpm lint`, R3 `pnpm typecheck` pass in that order; R4 contract command passes 90 files / 606 tests, including 11 request/commit regression tests and unchanged G0 output snapshots. Fingerprints are recorded by goal-loop. D1-D4/R5 remain unclaimed pending the remaining slice implementations.

## S2.1: Runtime references and optional preparation

- core carries optional opaque LayoutRuntimeRef on LayoutFragment and source reference maps through reflow. It has no plugin-api/runtime dependency and no persistent Schema fields. Viewer keeps fragments through toPagePlan and resolves bound props by reference rather than a virtual node id.
- Per-computation synchronous createSession is separate from implementation loading. Optional prepare runs once per included source after fonts, loading, bindings and beforePagePlan, using declared geometry; reserved/removed nodes are not prepared. Computation resource scopes are separate from output-item scopes and are released at completion, failure, cancellation or destroy. Late acquisitions self-release.
- Copies and per-page overlays retain the content reference while receiving independent page/copy context and output resource scopes. Page arrays are independently owned; an initial duplicate-overlay regression from sharing copy arrays was fixed, and original G0 snapshots pass unchanged.
- Public behavior tests verify two same-type sources, bound props, prepare/measure ordering, copy/pageAware inheritance, new references on rerender, cancellation during external preparation and acquired/late cleanup, plus local prepare/measure recovery.

## S2.2: Private table fragment state and pagination progress

- table-data's full Viewer entry uses createTableDataSession. Its private reference map holds source rows/rowHeights/totalHeight from original declared dimensions; measure/render reuse this state without expanding the original table again. Module runtimeLayoutCache is removed.
- The unchanged row split algorithm derives separate current/next row and height arrays through framework createFragment. Remaining body row counts exclude repeated headers/footers. The generic Viewer wrapper checks non-negative safe-integer progress, owned references, new identities and a strictly smaller next count; invalid pagination stops the source with declared geometry and a diagnostic placeholder. ## S3.1: Bounded resource waits and fixed font selection

- Font catalog, provider and target-document FontFaceSet readiness are cancellable and bounded by the central 3,000 ms stage budget. Provider completion or style injection alone is not readiness. Failed/timeout selections become sans-serif before measurement.
- Provided fonts use unique request-local CSS family aliases. Successful output keeps its own FontManager rules; another Viewer, refresh, timeout or cleanup cannot replace or remove them. Timed-out providers never inject; late face completion cannot change the committed fallback.
- Candidate img/srcset and inline CSS background images are decoded concurrently before publication; failures/timeouts produce visible placeholders and diagnostics. Detached images load eagerly and fallback event listeners are removed on cancellation/timeout.
- Structural validation (2026-10-12): 3 files / 25 tests pass (resource-readiness, render-session, unchanged G0 snapshots). This does not claim actual browser readiness. D1/D3 still await real-browser checks; S4 output ownership remains pending. No Gate exit claimed.

## S4.1: Fixed output users and unified task results

- Print/export wait for the latest successful render in the current document, follow reentrant/superseding updates, reject the latest framework failure, and cancel unstarted output on open/destroy. Once acquired, the task holds the committed request's schema/data/metrics/diagnostics and its own version container.
- Preview and started tasks each own an internal use right. Replacement/open parks actively used original DOM in a connected container in its target document; real listeners, canvas and request-local fonts remain owned until the final user releases. No HTML cloning or public lease API. Computation cleanup cannot abort output-item resources.
- Viewer print/export return completed/cancelled discriminated results, with diagnostics and an optional export file. Overall errors reject; Viewer throwOnError is removed. Playground and managed print direct callers migrated; other print SDKs keep their existing error option.
- Destroy cancels library-owned output waits promptly, suppresses late callbacks and export-after-prepare, and observes acquired async cleanup without waiting for uncancellable external work. Task rights release in finally on success/failure/cancellation.
- Validation (2026-10-12): 5 files / 62 tests pass, including seven ownership regressions using a material that acquires real DOM listeners. Old API assertions were migrated; no Gate exits or D4 claim yet. Real-browser output/cross-document verification and R1-R5 remain for the next slice.
