## Source Decisions

本计划将 [地图](./map.md) 与 [交付路线](./roadmap.md) 编译为执行合同；接口、行为和取舍以 Contract Sources 中各票据有效 Answer 为准。十张票据均已 resolved。evidence/ 和 architecture-audit.md 是历史事实/处置索引，不恢复已撤回的兼容、可选插件跳过或通用插槽方案。

原路线 UI 与 Render Session 可并行，本控制面采用 G0 → G1 → G2 → G3 → G4 → G5 → G6 线性顺序；G4 技术上依赖 G2，执行前驱为 G3。此排序不增加架构依赖。初始化只激活 G0，尚未执行任何实现或应用验收。

## Outcome

完整迁移物料能力装配层，保持文档 Schema、codec、migration、持久化版本和正常编辑/渲染语义；删除旧装配 API；所有真实消费者和候选制品验收通过后，一次交付 0.1.0 供用户手动发布。规划完成、重构完成和可手动发布分别报告。

## Non-Negotiable Rules

- 完整物料为普通使用单位；共享模型及集合成员关系各一份来源，builtin 只组合；默认 all，保留 basic/none 与自行组合。两端入口隔离，Viewer JS 与声明图不引入 Designer/Vue/Assistant UI。
- 每实例唯一装配内核，回调直接获得受控上下文，不暴露 Store；创建失败整体清理，可等待 destroy、代次失效与迟到资源自清理。首版换集合通过销毁重建。
- Schema/codec/migration/节点工厂语义不变；runtimeRef 不进入持久化节点。保留正常夹具；未知物料可见诊断与核心配置错误严格区分。locale 冲突非阻断，不恢复可选插件跳过模式。
- 同一可交接实现变更按 R1 build → R2 lint → R3 typecheck 顺序检查，再执行相关行为测试；命令失败保持 active 修复，不把普通测试失败作为 Stop condition。不可为过门禁添加兼容层。
- 每个 Gate 交接写 implementation/G<n>.md（相对本 effort），简记“决议 → 实际文件/exports → 测试/产物证据”，包含命令、环境、成功/失败/未验证、删除与保留项、实际 HEAD/本地差异、下一阶段输入。可执行夹具/消费样例放所属包 src/ 测试目录以纳入源码指纹；implementation/ 仅保存交接记录和清单；不改写 evidence/ 历史源码事实。
- 运行状态只能由 .agents/skills/goal-loop/scripts/goal_loop_ctl.py 写入，所有 mutation 携带最新 Revision；先完成代码和 Repository 检查，再写完交接记录、启动并完成 Directed 检查；Repository 指纹不包含交接记录，避免记录检查结果使自身过期。Directed 通过后再改交接记录或源码会使 fingerprint stale，必须重验。goal/ 不存完整输出、产物或证据副本。
- Repository 表仅列已存在的真实命令。新增契约、候选包隔离消费、依赖图和平台验证由 Directed 检查实际执行并给出证据，不能只阅读源码或复述要求就判 pass。缺测试、缺环境、skip 或候选路径不明都不算通过。
- R 检查针对源码/配置输入；D 检查还核对实际产物校验信息。不将 node_modules、构建缓存、goal/ 或滚动输出放入指纹通配符。每阶段必须核对新增文件是否落入既有 Evidence inputs，未覆盖时先修订合同。
- 架构文档随已落地边界更新，用户指南只讲可用 API；GLOSSARY 只存术语。重点章节 03/04/09/11/16/18/23/25 与渲染 06/24，Schema 章节核对不变量。源码和正式文档更新不自动改变票据决议；若必须修改 Contract Sources，先用 revise-contract preview/commit 审查更新 baseline。
- 公共契约、能力 owner、依赖、事务/失败语义、Session/输出寿命、默认集合或发布策略改变时，停止受影响 Gate 并修订对应决议。私有命名和同包组织可在既定边界内决定。
- 不预建性能基线；发现可复现变慢、异常包体或资源增长时补针对性数据和修复证据。资源残留与正常输出漂移仍为行为失败。
- Goal Loop 不创建、修改或回滚 Git commit。阶段检查点版本由用户 Git 流程负责。不得自动 release/publish/tag/push；任何未验证的发布必需项都阻止可发布结论。

## G0: 冻结行为与消费基线

### Purpose

把现有行为、删除范围和平台链路固定为后续可比较的证据。

### Inputs

地图、路线及票据 01–03、06、09、10；研究提交 0b43cb752ddd13b1802bbbb0d3b2993a3a8fd3be，审查/初始化 HEAD 042619cd952c9c32ffe66dab874193b7c99e27d6。实施时再次记录实际 HEAD 和本地改动，不把历史源码当作当前结果。

### Objective

冻结 canonical/normalize/codec 夹具、集合/目录/模型/locale/AI 快照；形成逐项旧 API/类型/exports/重导出/可写 registry → 消费者 → 删除或保留理由的清单；列出公共包及 private runtime、Go/Android 匹配关系。

### Scope boundary

允许补充 packages/schema、core、builtin、materials、designer、viewer 的基线夹具/公共行为测试，以及 implementation/ 下的清单与消费 fixture。只观察生产代码，不开始 Host、物料迁移或版本改写。

### Constraints

未知类型、自定义字段、条件、绑定、单位、图表、表格、分页、页码均须纳入；all 25/basic 17/none 及目录预设顺序按实际源码冻结。已知失败保留首因和复现条件，不修改 Schema 或历史 codec 行为使基线变绿。useTokens 无消费者，不新增机制。

### Slice policy

- S1：固定文档/数据与正常输出几何、内容、页数，记录已知失败。
- S2：冻结模型默认值、binding、condition/pageAware、目录/locale/AI 与集合；枚举全部消费/删除目标。
- S3：制作最小 Viewer 的 JavaScript/声明图与公共包、内嵌制品矩阵，提交 G0 交接记录。

## G4: Render Session 与输出所有权

### Purpose

以本轮状态和明确资源寿命替换隐式跨轮缓存，保证提交一致性。

### Inputs

G3 全部退出证据（线性执行前驱）；技术上依赖 G2；票据 08、05、10；G0 渲染夹具。

### Objective

实现快照/代次、可选 factory/异步 prepare、runtimeRef 贯穿片段和 page plan、table 私有状态、资源就绪/降级、最后提交与打印导出固定版本。

### Scope boundary

允许 packages/viewer、core 的非持久化布局传递、materials/table/data 与相关 text/line/flow-row/page-number/barcode/chart 实现、print/export 直接调用、internal-packages/viewer-runtime 测试，架构 06/24。复用现有算法，不新增按物料类型分支。另含 lib/EasyInk.Render/host 的最小 HTML 加载传输修复及其聚焦回归测试，以及 internal-packages/render-api-service 的跨平台 render-smoke 执行适配，仅用于完成 G4 R5；不扩展 host 公共协议、安全策略、输出语义或执行 G5 宿主切换。

### Constraints

loader 与同步 factory 分离；prepare 每源实例一次，可异步，在加载/字体/绑定/beforePagePlan 后、measure 前；其他计算接口同步。runtimeRef/resolved props 跨 reflow/分页/copies/pageAware/toPagePlan 保留但不入 Schema。表格原尺寸、rows/rowHeights/totalHeight 不重复累加，nextPage 剩余量严格递减且新身份，删除 runtimeLayoutCache。新请求失败也不恢复旧请求提交权；同文档失败保留旧输出、open 切文档清空。字体图片有限等待、迟到不改已提交结果。计算/候选/已提交/函数临时资源分开，最后使用方释放；保留图表 SSR 后立即 dispose。完成含诊断、取消不抛错、整体失败拒绝，删除 Viewer throwOnError 分支。

### Slice policy

- S1：快照、代次、提交屏障、统一任务结果及重叠更新/销毁。
- S2：非持久化引用与表格会话状态全通路，验证多级分页、复制和绑定继承。
- S3：字体/图片有限等待、局部故障与各物料特有回归；真实浏览器验证。
- S4：打印/导出跟随最新请求、开始后固定输出与 finally 清理，验证跨 document 和异步销毁。
