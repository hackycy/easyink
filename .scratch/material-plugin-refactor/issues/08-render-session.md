## Question

如何把复杂物料的跨测量、分页、渲染状态显式带到最终输出，保持既有计算语义，并分别管理计算状态和仍在使用的输出资源？

## Answer

本票经 2026-10-11 逐轮讨论收敛。以下为唯一有效契约及代码落实约束，替代早期候选方案。这里只完成路线规划，不表示源码已实现；具体字段拼写、私有文件及辅助函数名可由实施任务决定，不得改变下列公共行为与所有权。

### 本票最终决议

框架按轮创建渲染会话并捕获固定输入，只有最新请求可以提交结果。同文档刷新保留上一轮成功输出，切换文档清除旧预览。复杂物料可选会话实例与异步准备，简单物料保持同步函数；运行引用通过非持久化布局片段传递，Schema 不变。计算状态与输出资源分开清理，打印/导出固定一致的结果版本；局部物料或资源问题用占位、fallback 和诊断继续运行，整体任务无法完成才拒绝 Promise。

### 一轮计算与可见输出

- 每次触发计算的 open/updateData/render 对应一轮 Render Session，框架内部创建，无需调用方 begin/end。捕获文档、数据、声明尺寸、单位、目标 document、字体环境及已安装能力的本轮输入；后续修改原对象不能混入该轮结果。采用受支持数据的复制/归一化方式，不使用 structuredClone 或 JSON stringify 丢失值的方式盲目替代所有数据复制。
- 先请求 A 后请求 B，A 失去提交权；即使 B 失败也不恢复 A。等待资源后的检查以及最终提交检查都必须覆盖当前 Host、Scope、文档代次和会话有效性。迟到结果不能发布 DOM、页数、诊断或可见缓存。
- 同文档刷新等待期间保留上一轮完整结果；新结果准备好后一起发布 DOM、metrics、成功输入快照和该轮输出诊断。整体失败或取消只清理候选结果，保留旧输出；宿主独立暴露更新中/失败状态，不能把旧结果标为本次成功。
- 显式 open 视为文档切换，不比较 Schema 内容猜测身份。移除旧预览并显示加载/失败状态，取消尚未开始的打印/导出请求。首次失败没有可显示的旧结果，不伪造成功页面。
- 宿主状态和进度独立于已提交输出诊断；过期请求不得覆盖最新状态。候选 DOM 在独立容器中准备，必要时在隔离的连接环境中测量/加载，不提前替换当前可见页面。

### 物料声明与同步异步边界

无跨阶段可变状态的 text/image 等物料直接提供新的同步 renderer 实现，不强制填写 factory、prepare 或状态 Map。表格等复杂物料可声明会话 factory：框架每轮为所需物料创建独立实例，实例内以运行引用保存类型明确的私有状态。相同类型的多个节点及其片段也必须区分，不能共享一个不断覆盖的当前状态变量。

惰性 loader 负责取得实现代码；factory 本身同步，代码加载与状态实例化是不同责任。condition/pageAware 从共享模型读取，不在 renderer 重复声明。两种声明方式均属于完整物料入口，不恢复旧注册 API。

| 阶段 | 契约与职责 |
| --- | --- |
| 可选 prepare | 每个参与计算的源实例一次，允许 void 或 Promise；使用原声明尺寸和本轮绑定结果准备私有状态 |
| measure | 同步，读取准备结果，给出布局测量值；重复测量不得累加行高或改变状态 |
| 自定义分页 | 同步，拆分该实例内容，关联派生片段状态并报告剩余可分内容量 |
| render | 同步，返回 HTML/element；资源登记到当前输出项范围 |
| getRenderSize | 同步，保持最终 wrapper 尺寸职责，不提前替代布局 measure |

保留条件、绑定、测量、布局/分页、逐页处理和绘制的既有语义。框架在必要实现加载、字体就绪、绑定投影和既有 beforePagePlan 阶段之后、首次 measure 之前等待 prepare；每次 await 后重新检查有效性。被条件移除的节点不准备，reserve 节点沿用既有占位规则。prepare 之间不能依赖声明顺序读取其他物料的可变状态。

拆分片段由父实例状态派生，不重新展开原表；简单物料省略 prepare。同步方法不允许返回 Promise，异步工作集中在可选准备和框架资源阶段。失效请求不无限等待不可取消的外部 Promise；其迟到状态只归失效会话，迟到资源仍由清理处理器释放。

### 运行引用穿过布局与分页

用户确认在 core 非持久化 LayoutFragment 上增加可选不透明运行引用。core 仅携带，不解释物料状态，也不反向依赖 plugin-api/runtime。运行引用只用于本轮处理，不写入 MaterialNode、文档 Schema、codec 或序列化输出；应用不创建、传入或管理它。

| 代码落点 | 责任 |
| --- | --- |
| core/src/layout-plan.ts | 独立于插件层的可选运行标识形状；无引用的纯布局用例仍可用 |
| core/src/layout-strategy.ts、pagination-engine.ts | 接收源片段关联，移动、重排、复制时保留；实际拆分使用框架分配的新片段身份 |
| viewer/src/runtime.ts 的布局调度 | 建立引用到源节点、原声明尺寸、resolved props 的本轮关联；通过通用包装器接入物料分页 |
| Viewer 内部 toPagePlan | page item 保留 node、运行引用和 pageContext，不再只提取 fragment.node |
| viewer/src/render-surface.ts | 按引用取得片段输入，再调用 render/getRenderSize；不依靠虚拟 node.id 回查源绑定 |
| materials/table/data/src/viewer.ts | 会话实例维护行状态，移除模块级 runtimeLayoutCache |

运行引用可用 session/instance 身份实现；框架辅助方法为真正拆分的片段分配新身份，物料把拆分后的私有状态关联到这些身份。框架管理源节点和绑定关联，物料仅理解自己的拆分内容；核心不得添加按 table 等类型的分支。坐标移动不改变内容身份。

一张表格拆成两页时，两页关联同一个原文档节点，各自取得对应行状态。复制页/逐页元素可共享只读计算数据，但每次输出有独立资源范围与 pageContext；最终页码、总页数和 copyIndex 不写回共享 prepared state。

已安装 renderer 的运行引用缺失、越界或属于失效会话时诊断并占位，不启用旧隐式缓存兜底。未知物料占位无需建立它不存在的私有状态。

### 表格状态与分页进度

表格保留原展开行、自动行高、拆行和绘制算法。prepare 根据源节点、本轮数据和原声明高度产生 rows、rowHeights、totalHeight；本轮实例保存声明尺寸基线及各片段状态。measure/分页/render 共用结果，不能用测量后的 node.height 再次计算缩放。

源片段与子片段不共享可变行数组；只读结构可共享。分页由现有算法决定当前页/剩余内容，通过框架分配新引用，分别保存对应行和行高。片段不再重新绑定或展开整张表，resolved props 继承关联不因虚拟 id 改变而丢失。

只有实现自定义分页的物料需要报告剩余可分内容量；值为非负安全整数，返回 nextPage 时必须严格小于父片段且使用新引用。表格以剩余正文行数计数，不计重复表头/页脚。无进展拆分不被接受，停止该项并诊断/占位，其他物料继续。不能用任意页数上限截断合法长文档。已知无法容纳一行等正常 overflow 沿用已有规则并停止继续拆分，不改变正常分页夹具。

### 字体图片就绪与降级

影响排版的已声明字体在目标文档中就绪后才测量，不能把 FontProvider 返回或 CSS 注入等同字体实际可用。本轮图片等已知资源在候选输出提交前完成加载/解码检查，框架统一等待，作者和调用方不额外调用 waitImages/prepareFonts。只检查当前结果实际使用的资源，不等待整个宿主页面的无关请求。

资源等待有集中定义、有限且可取消的预算，具体默认值在实现配置中记录和测试。字体失败/超时使用确定 fallback，图片失败/超时使用可见占位，均带诊断且不阻断其他内容。降级后的资源选择属于该输出版本，迟到字体/图片不能悄悄改变已提交结果，需要重新渲染才生效。

无 DOM 的纯计算不伪造图片解码成功，实际产生页面的渠道承担其就绪检查。跨 document 重新生成输出时检查该目标环境，沿用降级与诊断。未声明的外部脚本、动画或任意第三方副作用不在就绪保证中。

### 局部故障与整轮故障

可隔离的实现加载、prepare、measure、分页、render/getRenderSize 或输出资源失败，只影响对应源节点/片段。清理其未提交资源，停止继续使用部分状态，以框架通用占位保留来源、节点和阶段诊断；不能再调用失败物料的方法来计算占位。

测量/分页失败使用原声明尺寸等已知有效几何占位，不承诺失败物料本应有的内容与页数；绘制失败保留已完成布局的片段几何。其他节点继续。能提交的降级结果为“已完成但有问题”，可继续预览/打印/导出，不静默删除内容，也不强制新增确认弹窗。应用可根据诊断采用自身输出策略。

翻译、字体 fallback 等已有恢复规则不统一升级为物料占位。无法保证整体布局/输出一致性的框架级故障使本轮失败，同文档情况下保留上一轮结果；缺少必需模型/renderer 等声明错误仍按创建事务处理，不被运行时降级吞掉。

### 资源与提交屏障

框架上下文提供 signal 与 onDispose，物料取得资源时登记清理，不自行创建或关闭 Scope、管理引用数。

| 资源范围 | 取得位置 | 释放时机 |
| --- | --- | --- |
| 本轮计算状态 | factory、prepare、measure、自定义分页 | 本轮结束、取消或失败；迟到资源自清理 |
| 候选输出项 | render/getRenderSize 的 DOM、订阅等 | 项失败或候选取消时清理；提交成功后由输出持有 |
| 已提交输出 | 页面、对应输入/页数、资源选择、输出资源 | 最后一个预览或已开始输出任务释放后清理 |
| 单次函数临时对象 | 如 SSR 图表转 SVG 时的绘图库实例 | 函数内 try/finally，使用完立即释放 |

当前 Viewer 图表生成 SVG 后即 dispose，不能声称旧页面上存在其活动实例；本轮不把静态图表改成交互图表。可见 SVG DOM 的寿命仍长于计算。

候选结果在资源就绪并再次检查有效性后整体提交。Session 临时状态随计算结束清理，不能连带 abort 已提交输出的 signal 或移除 DOM；输出事件如需数据应持有最小只读数据，不能依赖已清理的 Session Map。

预览与已经开始的打印/导出任务分别持有内部输出使用权。替换/切换只释放预览持有权，任务仍使用的旧输出保留到任务结束后 finally 释放。不能只保存可被刷新改写的 host.mount 引用，也不能仅 clone HTML 就假设 canvas、事件、字体和连接环境均已隔离；实际渠道须固定自身容器和资源环境。没有公共 lease/retain/release 配置。

Host destroy 先同步失效并停止库内工作，后清理会话、候选输出及可释放的输出资源，最后释放 Host 能力，清理错误继续并汇总。无法取消的外部任务不无限阻塞销毁，迟到结果不可写回且资源自清理。对已交付浏览器/打印服务的任务不承诺撤回。

### 打印导出与任务返回

打印/导出等待当前文档最新更新成功，等待中有同文档新请求则跟随最新请求；最新整体渲染失败则停止本次输出并给出原因，不静默输出旧页面。开始输出后固定同轮文档、数据、页数和输出资源，后续刷新不能改变任务内容。切换文档取消尚未开始的输出，不悄悄改为打印另一文档。

open/updateData/render 和 Viewer print/exportDocument 采用一致结果语义：

| 情况 | 结果 |
| --- | --- |
| 完成或带局部问题完成 | 返回完成状态、对应结果与诊断；导出附带渠道实际产生的文件（若有） |
| 正常被替代、切换或销毁取消 | 返回取消状态及原因，不抛错，不把旧结果伪装为本次结果 |
| 整体无法完成任务 | 拒绝 Promise，保留失败原因；Viewer 未销毁时仍可重试 |

结果采用状态判别类型，具体字段名由实现整理。删除 Viewer print/exportDocument 的 throwOnError 分支，直接调用路径同步迁移；不借此统一改造所有打印 SDK 的公共接口。取消只报告库可确认的事实，浏览器对话框未可靠报告时不伪造“用户取消”或“纸张已打印”，成功阶段按渠道可观察的交付行为表达。

输出携带本轮局部降级诊断；使用已渲染页面的渠道保留占位，重新生成页面的渠道遵守同样规则并返回自身诊断。最新失败、正常取消与带诊断完成不可混同。

### 实施验收

- 双 Viewer 共用输入、重叠更新、字体/loader/prepare/图片等待中销毁均不串状态；旧轮不能写回 DOM、metrics、活动诊断或缓存。
- 同文档失败保留旧完整结果，切换文档清预览，候选提交版本一致；取消不误清理已显示或正在输出的资源。
- 表格原高度、行高、重复测量、深层分页、重复表头/尾和进度终止正确；绑定值与运行引用跨重排、分页、toPagePlan、copies、pageAware 保持关联。
- 简单物料无需会话 factory/prepare；复杂物料无模块级跨轮运行缓存；文档和序列化结果无运行字段，core 无插件依赖。
- prepare 可异步，其余计算接口同步；取消不抛错，整体失败拒绝，局部占位完成带诊断；调用方和类型 fixture 覆盖对应分支。
- 字体与图片检查在真实浏览器验证，覆盖失败、超时、迟到不改已提交输出，以及不同 document 的输出环境。
- 打印/导出等待最新结果，开始后版本固定；刷新或切换不提前释放其资源，已开始任务结束后释放，失败和销毁继续清理。
- 正常 text overflow、line、flow-row、page-number、barcode ownerDocument、table、chart-custom 的页数、几何与内容对照冻结基线；不重写正常布局/分页算法。

## 决策历史与源码依据

用户于 2026-10-11 逐轮确认连续更新、保留旧输出、打印/导出版本、局部失败、会话实例、prepare/分页进度、异步与取消返回、资源就绪、输出返回规则及运行引用落点。旧“所有 prepare 同步”“取消即清理当前可见输出”“必须为简单物料写 factory”“依赖共享模块缓存”“运行引用写入 Schema”方向不作为实施契约。

核查路径包括 viewer/src/runtime.ts、render-surface.ts、font-loader.ts、print-service.ts，core/src/layout-plan.ts、layout-strategy.ts、pagination-engine.ts，materials/table/data/src/viewer.ts 及 chart/kernel/src/core.ts、full.ts。当前代码在字体等待后仍读可变输入、先写 metrics 再清 DOM 绘制，toPagePlan 仅提取 node，表格依靠 table 对象 WeakMap 关联状态；本票要求针对这些真实通路迁移。源码事实与目标契约须区分，本文档校验不代表上述应用行为已验证。
