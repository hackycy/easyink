## Question

如何证明架构契约落实、旧装配完整删除且行为未退化，并在完整重构完成后交给用户手动发布 0.1.0？

## Answer

> 2026-10-11 用户回复“接受”，本票 resolved。确认四层门禁、代表性行为与真实产物验证、文档单一权威和人工发布交接。2026-10-11 用户进一步明确：本次暂不建立性能基线；若实现过程中出现明显性能回归，再针对性补测。以下为最终验收决议；应用实现和测试仍未执行。

2026-10-08 曾确认分层门禁、先测性能基线和文档单一权威；2026-10-11 用户明确暂不需要性能基线，该项由本票最终决议取代，改为出现可复现回归时针对性补测。2026-10-10 按用户要求改为一次 0.1.0 破坏性发布，增加旧 API 不可用和完整切换门禁，取消兼容窗口验收。架构路线完成与代码重构完成分别报告。

### 四层门禁

| 层级 | 执行入口 / 环境 | 失败判据 / 时机 |
| --- | --- | --- |
| 提交级 | `pnpm build` → `pnpm lint` → `pnpm typecheck`；相关 Vitest | 编译/声明/行为任一失败；每个可交接实现变更 |
| 阶段级 | [阶段验证矩阵](../roadmap.md#验证矩阵)、类型消费 fixture、双 Host / Session 测试 | 与有效决议、冻结行为或所有权不符；阶段退出前 |
| 发布级 | `pnpm test`、`pnpm docs:build`、`pnpm render:runtime`、`pnpm render:manifest`、真实 render smoke、包消费/产物图验证 | 实际宿主、文档、0.1.0 版本/依赖/exports 或内嵌制品不一致；手动发布交接前 |
| 路线级 | `check-map.mjs validate`、决议语义复核、审查缺口处置索引 | 未决问题、死链、矛盾 Answer、无责任归属的能力/资源或阶段门禁；规划交接前 |

结构检查只读且不证明设计语义正确；resolved 不等于类型草案已编译，更不等于应用测试已通过。类型草案先在内核阶段落实为真实 package 源码和消费 fixture，再允许依赖它的阶段交接。

### 必须验证的行为

- Schema：canonical 夹具、codec/normalize/migration、未知物料、binding/table/chart/page 字段和版本；不借本次修复历史 codec 损失。
- 能力：默认 all、basic、none、自选完整物料、自定义完整物料、独立 Designer UI 扩展、无 UI Viewer；实际消费使用宿主完整物料入口，不要求模型/renderer/UI/AI 分别安装。模型与 renderer 可独立验证实现；自定义 renderer 仍通过完整物料交付。condition/pageAware 唯一模型归属，不能因 renderer 替换漂移。现有 all 25 种、basic 17 种以及目录/预设按冻结基线核对；缺少可选能力与迁移时误删已有功能分别判断。
- 所有权：核心能力冲突整体失败、重复物料/插件身份不覆盖、捕获核心注册异常仍失败、最终能力检查、cleanup 异常继续、重复 destroy、迟到结果自清理。首版不提供插件依赖排序配置，不保留已撤回的可选插件失败跳过模式。
- 文案容错：翻译缺失或同级词条冲突不阻止启动/编辑/预览/打印；同值共享、异值稳定选择并可查来源，诊断去重，宿主显式覆盖保持优先。
- 编辑：factory/lazy、drop、resize、selection、属性/overlay、transaction、撤销重做、Assistant manifest 与 UI、双 Designer Teleport 隔离。验证五类 Designer UI 的位置、排序和 context，属性 append/replace-body 范围，局部 UI 故障不破坏编辑器；普通节点编辑可撤销，setSchema 和 Assistant 替换/回退保留已确认的历史/选择/编辑会话语义。预览壳层留在输出 iframe 外，不新增 Viewer UI 包或通用属性前后插槽。
- 渲染：条件/绑定/measure/layout/pagination/page-aware/render 顺序，text wrapper、line、flow-row、table rows/fragment、barcode ownerDocument、chart lazy；输出结构、几何、页数和内容与基线比较。
- 会话：双 Viewer 同 Schema 不串数据；每轮固定输入，只有最新请求可提交 DOM/metrics/diagnostics，即使新请求失败也不能让旧请求重新获得提交权。同文档刷新失败保留上次成功输出并显示状态，open 切文档清旧预览；源/片段状态和运行引用穿过 reflow/copies/toPagePlan，不写入 Schema。table 的私有会话状态、可选 prepare 时序、分页剩余工作量递减均有实际行为验证。
- 输出与故障：字体/图片有限等待后允许可诊断降级；单物料 load/prepare/measure/paginate/render/getRenderSize 失败可见占位，框架无法形成一致布局才整体失败。打印/导出等待最新成功结果，失败时不静默使用旧结果；输出任务开始后固定版本。正常取消、带诊断完成、整体失败可区分，Viewer 不保留 throwOnError 分支。浏览器打印只验证可观察到的交接，不能声称确认纸张已输出或用户最终选择。
- 资源：取消候选任务只释放自身资源；计算资源和输出资源分开。预览替换时已开始的打印/导出仍能使用固定输出，最后使用方结束才释放；destroy、清理异常与不可取消的迟到结果均覆盖。当前 Viewer 图表 SSR 生成 SVG 后即销毁引擎，保持该行为，不为了测试凭空增加常驻图表实例；需要验证输出持有期时用确实持有资源的测试物料。克隆 HTML 不假定可以保留 canvas、事件和字体环境。
- 破坏性切换：旧 bundle/注册/Contribution 类型和导出不可用；无兼容 façade/第二存储；全部消费者直接用新配置；旧 API 负向消费检查明确失败，新 API 示例成功。
- 包：workspace 无循环；exports 独立声明入口；最小 Viewer JS 和 `.d.ts` 不拉入 Vue/Designer/Assistant UI；chart-custom lazy 未退化。验证单物料、all/basic/none 的源码和实际打包入口，以及内嵌 runtime 的真实产物图；动态 import 本身不能证明隔离。0.1.0 候选包在隔离的消费项目中验证运行和类型，不能只靠 workspace 链接成功。

测试以公共行为、已确认边界和真实回归风险为依据，复用现有夹具与测试入口。不为每个私有函数或文档改字新增测试；不要求所有物料重复跑相同的完整交叉矩阵。通用框架规则用代表性物料和故障注入覆盖，各物料保留自身特有行为与已有能力检查。

真实字体/布局/打印不能由 happy-dom 替代。浏览器未配置、Go 集成缺少 `EASYINK_RENDER_BROWSER_PATH` 或 Android 构建环境缺失导致 skip，要记录未验证，不能作为发布通过。现有命令具体前置条件从实际脚本读取，不能把计划命令记作执行结果。

### 性能范围

本次重构当前不建立包体、冷启动、大表格耗时或重复挂载计数的性能基线，也不把性能预算设为阶段前置条件。现有功能和架构目标没有显示出需要专门性能治理的风险，实施阶段先完成正确性、资源所有权、依赖隔离和真实宿主验证。

如果实现过程中出现明显变慢、包体异常膨胀、重复挂载资源增长或其他可复现的性能回归，再记录受影响场景的前后数据，针对该问题补充性能门禁。资源残留、输出错误、布局/页数漂移和功能回归仍按行为门禁处理；不以“暂不做性能基线”掩盖这些问题。重复物料/插件身份的显式失败需写入 release notes；locale 冲突继续按稳定选值与非阻断诊断处理。

| 内容 | 唯一权威位置 | 更新时机 |

| 领域名称 | 根 GLOSSARY.md | 概念含义变化时；不写接口签名 |

票据允许暂存待实施最小契约；落地后以源码为权威并从票据链接，不长期复制整套 API。必要 ADR 只提升难逆转且有真实取舍的结论，原票保留摘要和链接。正式架构文档目前继续讲现有代码，不能提前假装 plugin-api 已存在。

实现需要同步核对架构章节 03/04/09/11/16/18/23/25 和渲染章节 06/24；Schema 章节只检查冻结不变量。默认 all/basic、自选物料、完整新增物料、独立 Designer UI 扩展、无 UI Viewer 示例必须能实际构建。renderer 定制示例通过完整物料提供，不另教用户拼装多份能力插件。物料票据的完整入口、目录随物料、AI manifest 和 Viewer 依赖隔离必须有实际消费 fixture。文档中的代码尽量复用这些可构建例子，避免另存一套无法验证的调用方式。

### 0.1.0 人工发布交接

实现负责人记录命令、环境、失败与未验证项；包维护者核对版本/exports/声明与移除清单；宿主维护者核对 playground、print 和 Go/Android 内嵌制品；文档维护者核对所有教程和 breaking changes。角色可由同一人承担，但证据不能省略。

按[破坏性切换决议](./09-compatibility-cutover.md)生成 0.1.0 公共包清单、候选产物、版本匹配说明、release notes、迁移范例和回退说明。完整验收后交用户手动发布；构建完成不自动执行 release/publish/tag。没有 N/N+1 观察窗口，不因外部用户尚未迁移而保留旧实现。

每个实现阶段交接“决议要求 → 实际文件/导出 → 测试/产物证据”，记录通过、失败、未验证及环境。环境缺失可以继续独立实现工作，但发布必需项未验证时不得标为可发布。发布准备要核对新增包首次发布前提和现有 tag workflow 副作用，不能为验证发行准备而实际触发发布。

路线收敛后先做一次全图语义与链接复核，再交接阶段零的行为夹具、消费清单和删除清单工作；性能基线不属于阶段零必交件。规划完成、重构完成、可手动发布分开报告；地图决策全部 resolved 只证明第一项。实现中的私有命名、同包文件组织与等价内部优化由实现者决定；公共契约、能力归属、失败语义、资源寿命或发布策略需要改变时，先记录证据并修订对应决议，不私自偏移。
