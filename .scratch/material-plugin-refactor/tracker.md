# 地图维护与交接约定

本目录采用本地 Markdown issue tracker，随仓库版本管理。读取入口是 [map.md](./map.md)，交付阶段见 [roadmap.md](./roadmap.md)。这些规则独立于本地技能文件和外部服务，另一位开发者只读取仓库即可继续。

## 文件职责

- `map.md`：目标、约束、已决事项的摘要链接、尚不能明确描述的问题及不在范围内的工作。
- `issues/NN-*.md`：一个研究或决策问题；该问题的推荐方案、验收和最终答案只保存在这份票据。
- `evidence/`：固定来源版本的研究事实；不当作不断变化的接口文档。
- `roadmap.md`：阶段顺序、实施门禁与交接；不复制票据的实时状态。
- `architecture-audit.md`：审查历史与处置链接；不保留第二份有效契约。
- 根 `GLOSSARY.md`：领域术语；不存接口签名与迁移步骤。

## 票据字段

```text
Type: research | grilling | prototype | task
Labels: wayfinder:<与 Type 相同的值>
Status: open | claimed | resolved
Assignee: none | 驱动本票的人或代理
Parent: 地图的相对 Markdown 链接
Blocked by: none | 04, 05
```

目录编号是身份，标题是人阅读时的名称；叙述和链接使用标题。只加 `wayfinder:` 标签，架构决策不标成可直接实现的开发任务。阻塞编号只表示依赖，所有编号必须有对应文件。

前沿是 `open`、未认领、所有阻塞票均 `resolved` 的票据，按编号排序。`claimed` 必须已有 Assignee；`resolved` 必须有 `## Answer`。多个会话不得同时编辑同一票据。

## 开始一次会话

1. 读取地图，核对本轮目的为建图、研究、决策或实施；不要把草案 API 当作已落地代码。
2. 运行 `node .scratch/material-plugin-refactor/check-map.mjs frontier`；用户指定票据时检查其阻塞条件。
3. 先保存认领：`Status: claimed`、`Assignee: <当前驱动者>`，再深入调查或讨论。
4. 只按需加载相关票据和证据。源代码变化后追加新事实与基线，不悄悄重写旧研究为当前事实。

## 关闭或重新打开

- 研究用一手来源、文件路径和固定版本核实，可以并行完成。设计选择需要实际人与方案的讨论，不把代理建议伪装成人的确认。
- 设计票逐项收敛；`Answer` 写明结论、取舍、适用范围、验收与确认来源。采用推荐方案也需写答案，不能仅改变状态。
- 本地 tracker 以 `## Answer` 作为 resolution comment，设 `resolved`，然后在地图 `Decisions so far` 加一行摘要链接。过程讨论可追加到 `## Comments`。
- 新问题先创建票据，拿到真实编号后再写 `Blocked by`。已有明确问题即使被阻塞也应建票，不放在地图的模糊事项里。
- 不再需要的票据仍保留身份，标 `resolved` 并在 Answer 记录“移出范围”及原因；只进入地图 Out of scope，不列入 Decisions so far。
- 决议被推翻时保留旧 Answer 的历史说明，把本票改回 open / unassigned；地图撤去有效决议摘要，复核依赖票据并重开受影响的结论。不能让下游以失效决定继续实施。
- 关键决定需要 ADR 时先完成真实取舍，提升后票据指向 ADR，不维护两份完整决议。

## 2026-10-10 决策更新与实施约束

用户在本会话要求补齐审查缺口，并明确取消旧 API/兼容层、完整重构后手动发布 0.1.0。此前代理同时补写受影响票据并过早标为 resolved；用户要求继续 wayfinder 讨论后，现已重开。用户明确确认的发布策略继续有效，代理新增的技术方案须逐票讨论，不能因曾写在 Answer 中而自动视为已确认。每次只收敛一张决策票，先认领再讨论。

evidence/ 和审查历史中的渐进迁移、旧入口适配建议属于固定版本记录；与当前决议不同之处已经被取代。历史源码事实仍可引用，旧推荐方案不得作为实现依据。

实施变更必须逐项关联有效决议、实际文件/exports 和验证证据。更改公共 Interface、能力 owner、事务边界、会话/输出寿命、包依赖或发布策略时先修订决策；私有函数名和同包文件组织可在既定边界内决定。不得为让旧示例通过而重新添加兼容层。

路线收敛后仍须完成真实代码、全宿主迁移、正式文档及 0.1.0 产物验收；发布由用户手动执行。本目录的检查器和 resolved 状态都不授予自动发布权限。

## 文档跟随实现

架构文档讲当前已落地边界；用户指南讲可用 API；地图讲已收敛路线和实施门禁。每次实现同时更新受影响文档。文档归属和发布门禁的决定见 [确定验收门禁、发布标准与持续文档归属](./issues/10-quality-documentation.md)。

用 `node .scratch/material-plugin-refactor/check-map.mjs validate` 检查本地图 Markdown、根 `GLOSSARY.md` 和架构 README 中的票据字段、依赖环、前沿、决议索引及本地链接。检查器只读；它不能替代仓库其他文档的链接扫描、源码核验、人的决策或应用测试。

地图的“建图完成”表示问题、证据、依赖与阶段路线齐备；“路线收敛”要求所有首版决策 resolved 且未定义事项清空；“重构交付”还要求实现阶段和发布验收完成。三者不能互相替代。
